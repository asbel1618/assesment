  Design

  1. Inputs: generate_orders(seed: int, n_base: int = 1000) -> list[dict[str, 
     str]] is a pure function that only uses its own random.Random(seed). It
     never uses the global RNG or set ordering, so the same seed always gives
     the same output. A thin main() takes --seed 42 --rows 1000 --out 
     <project>/data/orders_raw.csv, with the output path resolved from __file__
     so it works from any working directory. It creates data/ and writes with
     csv.writer(newline="").
  2. Columns: exactly the spec's: date, customer, country, product, amount, 
     status. No id.
  3. Clean base rows (1,000):
     - date: uniform over 2025-01-01…2025-12-31, ISO format.
     - customer: a pool of about 150 names built from first and last name lists,
       with skewed weights so the top 10 clearly stand out.
     - country: the 8 canonical names from §0.
     - product: about 10 products, each with a price range; amount = price ×
       qty, formatted 1234.50.
     - status weights: completed 75 / pending 10 / cancelled 10 / refunded 5.
  4. Defects, at most one per base row. This keeps the reject counts by reason
     exact and the README numbers clean.

  | Defect                   | Share | Examples                                |
  Step 2 outcome         |
  |--------------------------|-------|-----------------------------------------|
  ------------------------|
  | Valid date, other format | ~10%  | 14/03/2025 (always DD/MM), Mar 14, 2025 |
  parsed                 |
  | Invalid date             | ~4%   | 2025-13-45, 2025/02/30, 2O25-03-01, n/a |
  rejected               |
  | Missing amount           | ~3%   | "", N/A                                 |
  rejected               |
  | Formatted amount         | ~3%   | $1,200.50                               |
  coerced (see decision) |
  | Country variant          | ~6%   | spain,  SPAIN, Spain                    |
  normalized             |
  | Invalid status           | ~2%   | shipped, COMPLETED?                     |
  rejected               |

  5. Duplicates: about 80 exact copies of rows taken after defect injection, so
     some duplicates are themselves dirty. The whole list is then shuffled with
     the same RNG so duplicates aren't next to each other. Total is about 1,080
     rows.
  6. Tests (test_generator.py):
     - Two calls with the same seed give identical lists, and a different seed
       gives a different list.
     - At least 1,000 rows.
     - The header matches the spec columns.
     - Each defect class appears more than once, detected independently of the
       generator: a Counter for duplicates, regexes for date formats, value
       checks for amounts, statuses and country variants.
     - main() writes byte-identical files when run twice (using tmp_path).

  Decision needed before I implement

  - $1,200.50: §0 lists it as a defect, but the cleaning policy says invalid
    amounts are rejected. I'll treat it as formatting noise to clean up (parse
    it), and only reject empty values, N/A and non-numeric text. This affects
    step 2.
