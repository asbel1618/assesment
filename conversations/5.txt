     Step 4: Views

     Context

     PLAN.md §4 step 4. The spec requires two SQL views; together with orders,
     they are the only objects the LLM may query (they become the validator
     allowlist in step 5). State found during exploration:
     - scripts/load_orders.py::load_clean_orders already runs app/db/schema.sql
       and then TRUNCATE orders RESTART IDENTITY in one engine.begin()
       transaction. TRUNCATE was chosen over DROP so that views survive reloads.
     - docker/postgres/init/01-readonly-role.sh already runs ALTER DEFAULT 
       PRIVILEGES FOR ROLE <owner> IN SCHEMA public GRANT SELECT ON TABLES TO 
       app_ro. In Postgres, ON TABLES also covers views, so views the owner
       creates are readable by app_ro without any extra grant.
     - db and llm are running and healthy. The data is loaded (917 rows).

     Changes

     1. New coding_assesment/app/db/views.sql

     -- "Sales" = orders with status 'completed' only. Pending, cancelled and 
     refunded
     -- orders are not revenue (data contract, PLAN.md §0).
     -- SELECT for app_ro comes from the default privileges in 
     01-readonly-role.sh.

     CREATE OR REPLACE VIEW v_sales_by_month_country AS
     SELECT to_char(order_date, 'YYYY-MM') AS month,
            country,
            sum(amount)                    AS total_amount,
            count(*)                       AS order_count
     FROM orders
     WHERE status = 'completed'
     GROUP BY 1, 2;

     CREATE OR REPLACE VIEW v_top_customers AS
     SELECT customer,
            sum(amount) AS total_amount,
            count(*)    AS order_count
     FROM orders
     WHERE status = 'completed'
     GROUP BY customer
     ORDER BY total_amount DESC, customer   -- tie-break keeps the top 10 
     deterministic
     LIMIT 10;
     Decisions:
     - CREATE OR REPLACE makes the file idempotent, so it can run on every load.
     - No ORDER BY in the sales view: sorting is left to the caller.
     - v_top_customers needs ORDER BY because it uses LIMIT.
     - No explicit GRANT ... TO app_ro in the file. The default privileges
       already cover views, and hard-coding the role would make the loader fail
       on any database where app_ro does not exist. Verification step 4 below
       confirms that the grant applies.
     - No :name tokens in the file, including comments: SQLAlchemy text() would
       parse them as bind parameters. :: casts are also avoided.

     2. Change coding_assesment/scripts/load_orders.py (2 lines)

     - Add VIEWS_SQL = ROOT / "app" / "db" / "views.sql" next to SCHEMA_SQL.
     - In load_clean_orders, right after the schema.sql execute, add
       conn.execute(text(VIEWS_SQL.read_text(encoding="utf-8"))). The views are
       created in the same transaction as the table, and the reload stays
       atomic.
     - Existing comments stay as they are.
