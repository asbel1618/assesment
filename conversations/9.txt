     Step 8: endpoint test with mocked LLM

     Context

     The spec requires a pytest test for the endpoint with the LLM mocked, and
     it must be hermetic: no Postgres, no network. Step 7 checked
     200/400/502/503 by hand and left the 504 paths and query_failed for this
     step. These tests make every error class in the API contract (PLAN §3)
     reachable and asserted, which a manual curl session can't guarantee.

     Approach

     Override the two leaf providers, not the service. Use
     app.dependency_overrides[get_llm_client] and [get_query_repository]
     (app/dependencies.py), so the real QueryService and the real validate_sql
     run. That way the test shows the validator holds end to end: when the LLM
     returns malicious SQL, the request gets a 400 and the repository is never 
     called.
     - Why not override get_query_service: the test would then skip the validate
       → execute chain, the part the hidden criteria care about most.
     - Why not patch httpx/SQLAlchemy: it reaches into infrastructure. The
       LLMClient/QueryRepository protocols exist so tests don't have to.

     File: tests/test_api.py (new, the only file touched)

     Fakes (structurally typed against the protocols, no inheritance needed):
     - FakeLLM(result: str | LLMError): records the questions it gets in calls;
       returns the SQL or raises.
     - FakeRepository(result: QueryResult | QueryExecutionError): records the
       SQL it gets in calls; returns the result or raises.

     Fixture/helper: _client(llm, repo) -> TestClient builds a fresh
     create_app() per test (no shared override state), sets both overrides, and
     returns TestClient(app). An autouse fixture monkeypatch.delenvs
     LLM_BASE_URL and READONLY_DATABASE_URL, so if an override silently stops
     applying, the test fails loudly (RuntimeError from create_*_from_env)
     instead of reaching a real service.

     Tests:
     1. test_happy_path_returns_rows: the fake LLM returns plain SQL over
        v_sales_by_month_country (fence/think stripping belongs to the real
        client and is already covered in test_llm_client.py). Assert 200; sql ==
        validate_sql(LLM_SQL) (reuses the validator's normalization, nothing
        hardcoded); repo.calls == [that sql]; columns/rows intact;
        Decimal("8084.52") serialized as the JSON string "8084.52"; a date cell
        as ISO; truncated passed through; the question arrives at the LLM
        stripped ("  how much…  " → stripped).
     2. test_invalid_sql_from_llm_is_rejected_before_execution: the LLM returns
        DROP TABLE orders → 400, code == "invalid_sql", the body's sql echoes
        the raw LLM output, the message is non-empty, repo.calls == [].
     3. test_llm_errors_map_to_gateway_statuses (parametrized):
        LLMUnavailableError→502 llm_unavailable, LLMTimeoutError→504
        llm_timeout, LLMResponseError→502 llm_bad_response; body message == 
        exc.reason, sql is None, repository not called.
     4. test_execution_errors_map_to_statuses (parametrized):
        QueryFailedError→400 query_failed (body carries the validated sql),
        QueryTimeoutError→504 query_timeout, DatabaseUnavailableError→503
        db_unavailable, base QueryExecutionError→500 query_error.
     5. test_blank_or_missing_question_is_422 (parametrized: "", "   ", {}, 501
        chars) → 422, llm.calls == [].

     Each error test checks the full ErrorResponse shape (code, message, sql),
     not just the status (step-8 "Done when").

     Reuse: create_app (app/api.py), get_llm_client/get_query_repository
     (app/dependencies.py), QueryResult + error classes (app/db/repository.py),
     LLMError hierarchy (app/llm/base.py), validate_sql (app/validator.py).
     TestClient ships with fastapi[standard], so no new deps.

     No production code changes are planned. If a test exposes a real bug, stop
     and report it before fixing anything (global rule).

     Verification

     1. docker compose stop db llm (from test/), then uv run pytest -q passes in
        full (existing 119 tests plus the new ones).
     2. Sanity check that the tests can fail: temporarily change one mapping in
        app/routers/query.py (e.g. 504 → 502), confirm the matching test goes
        red, then revert (git diff clean). Done in the scratch working tree
        only, not committed.
     3. uv run ruff check . && uv run ruff format .
     4. Tick step 8 in PLAN.md and append a §8 AI-log row. Commit test: endpoint
        with mocked LLM only when the user asks.
