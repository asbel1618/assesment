     Design

     Pure core, thin CLI:
     - generate_orders(seed: int, rows: int) -> tuple[list[dict[str, str]], 
       DefectCounts] — no I/O, uses a local random.Random(seed) (no global state
       ⇒ deterministic).
     - write_csv(rows, path), main() with --seed (default 42), --rows (default
       1100, min 1000), --out (default data/orders_raw.csv). Creates data/ if
       missing; prints the defect summary.
     - DefectCounts frozen dataclass; asdict → manifest JSON.

     Generation pipeline (all rows are strings, as a raw CSV would be):
     1. Base: N_unique = rows − n_dups valid rows. Pools: ~60 customers (skewed
        weights so top 10 is meaningful), 8 countries, ~12 products with price
        bands, dates uniform over 2025-01-01…2025-12-31, status weights
        completed 70 / pending 12 / cancelled 10 / refunded 8, amount =
        lognormal-ish rounded to 2 dp.
     2. Defect injection on disjoint, randomly sampled row indices (so each
        count is exact and independently assertable):

     ┌──────────┬────────────────────────────────┬───────────┬────────────┐
     │          │                                │ Share of  │ Cleaning   │
     │  Family  │             Defect             │  unique   │  outcome   │
     │          │                                │   rows    │            │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Date     │ DD/MM/YYYY                     │ ~8%       │ parse OK   │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Date     │ Mon DD, YYYY                   │ ~8%       │ parse OK   │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │          │ invalid/misspelled:            │           │            │
     │ Date     │ 2025-13-45, 2025/02/30,        │ ~3%       │ reject     │
     │          │ 2O25-03-01, n/a, empty         │           │            │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Amount   │ $1,200.50 style                │ ~4%       │ parse OK   │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Amount   │ empty / N/A / garbage (abc)    │ ~4%       │ reject     │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Country  │ case/whitespace variants       │ ~8%       │ normalize  │
     │          │ (spain, FRANCE)                │           │            │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Customer │ whitespace/case variants       │ ~4%       │ normalize  │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Status   │ case/whitespace variants       │ ~4%       │ normalize  │
     │          │ (Completed )                   │           │            │
     ├──────────┼────────────────────────────────┼───────────┼────────────┤
     │ Status   │ invalid (complete, unknown)    │ ~2%       │ reject     │
     └──────────┴────────────────────────────────┴───────────┴────────────┘

     3. Duplicates (~8% of total, appended after dirtying, then whole file
        shuffled with the same RNG): mostly byte-exact copies, plus a few
        "normalized" duplicates differing only by case/whitespace to exercise
        dedupe-on-normalized-row (PLAN §0 policy).
     4. Day-first only (DD/MM/YYYY); force day > 12 for these rows so the format
        is unambiguous and the policy is documented rather than guessed.
     5. Header: date,customer,country,product,amount,status.
