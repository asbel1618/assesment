     Step 5 — SQL validator (TDD)

     Context

     LLM output is untrusted. validate_sql is the main safety control between
     the LLM (step 6) and execution (step 7); the app_ro role and read-only
     transaction are the second layer. Spec: PLAN.md §4 step 5. It must be pure
     (no DB, no network), importable, and covered by adversarial tests. Commit:
     feat: SQL validator + tests.

     Findings that shape the design (sqlglot 30.35.0, probed empirically)

     - sqlglot.parse(sql, read="postgres") returns [None] for "", "   ", ";"; a
       trailing ; gives one real statement; SELECT 1; DROP … gives two.
     - Prose either raises ParseError (hello world how are you) or parses to a
       non-query root (Total sales → Alias).
     - Data-modifying CTE WITH x AS (DELETE FROM orders RETURNING *) SELECT * 
       FROM x has a Select root → a root-type check alone is insufficient; the
       whole tree must be walked.
     - SELECT … INTO t → select.args["into"]; FOR UPDATE → args["locks"].
     - Schema-qualified tables set Table.db (public.orders → db=public).
     - Table functions in FROM (pg_read_file(...), ROWS FROM (...),
       generate_series) are Table nodes whose this is not an Identifier; LATERAL
       pg_ls_dir(...) shows up only as a function node.
     - Functions Postgres-useful for this domain (sum, count, avg, round,
       to_char, date_trunc, extract, date_part, coalesce, nullif, lower,
       string_agg, casts) parse to typed exp.Func nodes; every dangerous one
       probed (pg_sleep, pg_catalog.pg_sleep, pg_read_file, pg_ls_dir,
       lo_import, dblink, set_config, current_setting, txid_current) parses to
       exp.Anonymous.
     - Comments survive on nodes (node.comments); 'a -- b' inside a string
       literal is not a comment.
     - VALUES (1) → Values; EXPLAIN … → Command; COPY → Copy.
     - Unquoted identifiers: Postgres folds them to lowercase (Orders = orders).

     Approach

     Considered:
     1. Regex / keyword denylist — rejected: bypassable (case, comments,
        strings), the spec wants a parser.
     2. sqlglot AST, function denylist (pg_sleep, pg_read_file, …) — fragile:
        Postgres has hundreds of pg_*/admin functions; one missed name is a
        hole.
     3. sqlglot AST, closed-world allowlist (recommended) — allow only query
        roots, only allowlisted unqualified tables (+ CTE names), and reject any
        function sqlglot doesn't model (exp.Anonymous). A legitimate but
        unmodelled function gets rejected → 400, which is the safe failure mode;
        add names to an explicit allowlist only if real questions need them
        (starts empty).

     Design — app/validator.py

     ALLOWED_TABLES = frozenset({"orders", "v_sales_by_month_country",
     "v_top_customers"})

     class InvalidSQLError(ValueError):
         def __init__(self, reason: str) -> None: ...   # .reason used by the 
     router (step 7) for the 400 body

     def validate_sql(sql: str) -> str:   # returns ast.sql(dialect="postgres") 
     or raises InvalidSQLError
     Checks, in order (each raises with a specific reason string):
     1. Parse with read="postgres"; ParseError → "could not parse SQL".
     2. Drop None statements; 0 left → "empty query"; >1 → "multiple 
        statements".
     3. Root must be exp.Select or exp.SetOperation (UNION/INTERSECT/EXCEPT) →
        else "only SELECT queries are allowed" (covers Drop, Update, Insert,
        Copy, Command, Values, Alias).
     4. Walk tree:
        - any exp.Insert | Update | Delete | Merge → "data-modifying statement"
          (data-modifying CTEs);
        - any exp.Into / non-empty locks → "SELECT INTO / locking clauses not 
          allowed";
        - any node with comments → "comments not allowed".
     5. Tables: CTE names = {cte.alias_or_name.lower() for cte in 
        find_all(exp.CTE)}. For each exp.Table:
        - this not an Identifier → "table functions not allowed";
        - db or catalog set → "schema-qualified names not allowed" (blocks
          pg_catalog.x, information_schema.x, public.orders);
        - name (lowercased if unquoted, exact if quoted) ∉ ALLOWED_TABLES ∪ 
          cte_names → "table not allowed: <name>" (blocks unqualified pg_user,
          pg_roles, pg_tables too, also inside subqueries/CTE bodies).
     6. Functions: any exp.Anonymous whose lowercased name ∉
        _ALLOWED_EXTRA_FUNCTIONS (empty frozenset) → "function not allowed: 
        <name>".
     7. Return normalized SQL.

     Out of scope here (step 7): row LIMIT, statement_timeout, read-only
     transaction. A huge generate_series in the select list is a DoS concern
     handled by statement_timeout, not the validator.

     Tests first — tests/test_validator.py

     Run red (ModuleNotFoundError: app.validator), then implement to green.
     - Valid (parametrized, assert returns a str): plain select from each
       allowed object; aggregation + GROUP BY + to_char/extract; join orders ↔

     - Invalid (parametrized (sql, reason_fragment), assert InvalidSQLError and

       TABLE orders, UPDATE …, INSERT …, DELETE …, SELECT 1; DROP TABLE orders,

       data-modifying CTE, COPY, EXPLAIN, VALUES, pg_catalog.pg_user,

       pg_read_file in FROM, LATERAL pg_ls_dir, -- comment, /* comment */.
     - Literal 'a -- b' is accepted (no false positive on comments).
