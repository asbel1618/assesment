     1. Init script (01-readonly-role.sh)

     psql -v ON_ERROR_STOP=1 -v ro_password="$APP_RO_PASSWORD" -v 
     owner="$POSTGRES_USER" -v db="$POSTGRES_DB" with a heredoc; fail early if
     APP_RO_PASSWORD is empty. Password passed via :'ro_password' (psql-quoted,
     never interpolated by the shell into SQL).
     CREATE ROLE app_ro LOGIN PASSWORD :'ro_password';
     ALTER ROLE app_ro SET default_transaction_read_only = on;
     ALTER ROLE app_ro SET statement_timeout = '5s';
     REVOKE ALL ON DATABASE :"db" FROM PUBLIC;          -- drops TEMP (temp 
     tables are writable in RO txns) and CONNECT
     GRANT CONNECT ON DATABASE :"db" TO app_ro;
     REVOKE CREATE ON SCHEMA public FROM PUBLIC;          -- already PG15+ 
     default; explicit for readers
     GRANT USAGE ON SCHEMA public TO app_ro;
     ALTER DEFAULT PRIVILEGES FOR ROLE :"owner" IN SCHEMA public GRANT SELECT ON
     TABLES TO app_ro;
     Default privileges cover orders (created by the loader as owner) and the
     step-4 views, as already decided in PLAN.md. pg_catalog stays readable by
     default; the step-5 validator blocks it.

     2. Compose (db only)

     environment:
       APP_RO_PASSWORD: ${APP_RO_PASSWORD:?set APP_RO_PASSWORD in .env}
     volumes:
       - ./docker/postgres/init:/docker-entrypoint-initdb.d:ro

     3. app/db/connection.py

     create_engine_from_env(var: str) -> Engine: reads the env var, raises a
     clear RuntimeError if unset, returns create_engine(url, 
     pool_pre_ping=True). No dotenv dependency: host runs use uv run --env-file 
     ../.env …; in compose the env is injected.

     4. app/db/schema.sql

     orders exactly per PLAN.md §0 data contract (BIGSERIAL PK, DATE,
     NUMERIC(12,2) CHECK (amount >= 0), status CHECK IN (...)). Owned by the
     loader so schema lives in the app, not the volume.

     5. scripts/load_orders.py

     CLI mirrors scripts/generate_orders.py (argparse, defaults resolved from
     __file__): --input data/orders_raw.csv, --rejects data/rejected_orders.csv.
     1. pd.read_csv(path, dtype=str, keep_default_na=False) (contract required
        by clean_orders).
     2. clean, rejects = clean_orders(raw) (reuse app/cleaning.py).
     3. Write rejects (with reason) to the rejects CSV.
     4. One transaction, with engine.begin() as conn: (Postgres DDL is
        transactional): execute schema.sql → TRUNCATE orders RESTART IDENTITY →
        executemany INSERT … VALUES (:order_date, :customer, :country, :product,
        :amount, :status) from clean.to_dict("records") (date/Decimal bind
        natively) → SELECT count(*); raise if ≠ len(clean) (rolls back).
     5. Print: read, duplicates, rejected by reason
        (rejects.reason.str.split(";").explode().value_counts(), multi-reason
        rows counted per reason), rejected rows total, loaded.

     Idempotency: TRUNCATE + reinsert instead of DROP TABLE because step-4 views
     will depend on orders (DROP would fail or need CASCADE). Schema changes
     therefore need docker compose down -v.

     No new pytest: the loader is thin I/O around the already-tested
     clean_orders; DB behaviour is verified by the commands below (spec forbids
     network in tests).

    orders DDL, and scripts/load_orders.py is the loader.
  - The loader does TRUNCATE plus reinsert in one transaction, rather than DROP,

    data/rejected_orders.csv.

    - INSERT, DROP, CREATE TABLE and CREATE TEMP TABLE are all denied.

  - Lint and tests: ruff is clean and pytest passes (38 tests). I added no new
